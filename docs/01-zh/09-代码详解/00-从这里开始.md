# 从这里开始

这个文件夹有两种读法，可以来回点。

- **按功能看顺序。** 从 [说中文翻成瑞典语](功能/01-说中文翻成瑞典语.md) 开始。每一步写明用了哪个文件、发了什么事件、请求打到哪。全部功能在 [按功能看](功能/00-按功能看.md)。
- **按文件看段落。** 下面的目录里，每个源码文件有自己的一页，说明里面每一段在做什么，并配一个例子。

先读完这一页里的那句话和三条路。不必一次读完所有文件。

## 用一句话记住这个项目

孩子按下「说中文」。页面只负责把这个动作交给状态机。状态机决定下一步：录音、识别、理解、确认、翻译、朗读。真正去调用模型的是服务器。服务器里有三套可以互换的实现：假的 `mock`、云端 `cloud`、这台 Mac 上的 `local`。

例子：孩子要说「我想去厕所。」

1. 首页按钮发出 `START_TASK`，方向是 `ZH_TO_SV`。
2. 状态机进入录音。mock 下不必真的说话，点停止就得到这句剧本。
3. 点「说完了」。状态机去识别，得到文本「我想去厕所。」
4. 因为是中文，状态机再去理解。这句话意思清楚，模型返回「提出意思」。
5. 页面问：「你是说：我想去厕所，对吗？」孩子点是。
6. 这时才翻译，再朗读瑞典语。

点「是」之前不会翻译。这句话如果含糊，例如「他拿走了我的那个」，模型可以要求追问，但状态机最多允许 3 次。

## 三条路，互不占用对方的任务

- **说话翻译。** `apps/web/src/dialogue/machine.ts` 管。
- **拍照词卡。** `App.tsx` 用 `feature` 切换，不进入这台状态机。
- **监控。** 地址是 `/monitor`。它只记耗时和费用，不记孩子说了什么。

## 建议阅读顺序

1. [三个包](shared/index.md)，看两边共用的词。
2. [入口 main.tsx](web/main.md)，看页面怎么启动。
3. [界面 App.tsx](web/ui/App.md) 和 [屏幕 screens.tsx](web/ui/screens.md)。
4. [状态机 machine.ts](web/dialogue/machine.md)。这一页最长，按状态一段一段看。
5. [装配 runtime.ts](web/services/runtime.md) 和 [请求 apiClient.ts](web/services/apiClient.md)。
6. [服务器 app.ts](server/app.md) 和 [三套实现 registry.ts](server/providers/registry.md)。
